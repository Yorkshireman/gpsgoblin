# Proposed ticket: Convert a FIT activity to a GPX download on the person's device

**Status:** proposed 19 September 2026 and published at the owner's request on 20 September as [issue #55 — Add browser-based FIT activity to GPX conversion](https://github.com/Yorkshireman/gpsgoblin/issues/55). Updated on 20 September with the owner-agreed in-page preview and persistent download action. The issue is open with `needs-triage`; implementation, release and the change to baseline sequencing await owner acceptance. This document records the scope at this documentation revision; GitHub owns subsequent ticket changes. See [commercial review](commercial-review.md) and [primary-source research](fit-opportunity-research.md).

## Intended commercial outcome

Serve people who already possess a FIT recording and need its geographic content in GPX for another tool. Acquire relevant search visits through one useful `/tools/fit-to-gpx` page and a clear completed task. This expands task coverage and supplies decoding reusable by later viewers. Incremental traffic, advertising approval and profit are hypotheses; no volume or earnings forecast is attached.

The concrete compatibility rationale is that, for example, [Google My Maps documents GPX imports but does not list FIT](https://support.google.com/mymaps/answer/3024836?hl=en). Its restrictions still apply; do not promise arbitrary destination compatibility or advertise a tested integration before testing it. Garmin/Strava owners may already have a simpler GPX export path. Do not claim that Komoot requires conversion: its own documentation accepts FIT.

## Bounded scope

One local, uncompressed `.fit` **activity** file at a time; one explicitly selected session exported as a new GPX 1.1 track, preserving separate sections. A single session is selected automatically; multiple sessions require a choice with clear identity and available source summaries. Preserve the full imported structure so choosing one session never merges or destroys the others.

Export valid coordinates and available original timestamps/elevation. First-release GPX output does not promise sensor extensions, device totals, lap/event semantics, developer fields, workout instructions or course cues. State these losses before download. Original FIT bytes remain unchanged. No batch/ZIP handling, repair, smoothing, stop removal, FIT course/workout/settings conversion, provider accounts, new format viewer page or comparison work.

Use the shared import/model boundary and existing visual language. A small conversion summary and geographic preview are sufficient; a standalone FIT viewer and a general framework are not prerequisites. For a valid indoor activity without usable positions, retain available recording identity/source summaries and explain why GPX export is unavailable.

After successful conversion, offer **Preview converted GPX** beside the primary **Download GPX** action. Reuse the existing GPX viewer within the converter page, displaying the actual generated file. Keep Download GPX visible beside the converted file's identity throughout preview so inspection never feels like losing access to the download. Closing preview restores the conversion summary without losing the original FIT, session selection or generated file.

## Acceptance criteria

- [ ] **Dependency gate:** assess the maintained decoder, beginning with Garmin's JavaScript FIT SDK, for its actual licence/distribution obligations, browser/worker/Jest compatibility, bundle size and memory. Record the decision. Stop and surface any incompatible obligation or required spending before adoption; no dependency is approved merely by this proposal.
- [ ] **Content validation:** detect FIT structure and file subtype; distinguish unsupported course/workout/settings content from corruption. Handle truncated or invalid input without presenting a partial decode as a complete success. Publish tested exporter/subtype coverage and fixture provenance. No personal recordings may be committed without permission.
- [ ] **Data model:** keep source order, original values and stable sample/session relationships. Preserve sessions, relevant laps/events and available fields behind the adapter; mark unsupported interpretation explicitly. Do not turn missing or invalid coordinates, elevation or times into zero or guessed values. Keep source totals distinct from any calculated preview values.
- [ ] **Preservation policy:** document and test how session boundaries, invalid/missing positions, recording discontinuities, duplicate/backwards/missing times and timer events map to GPX sections. Do not sort samples, interpolate points, bridge omitted sections, treat every timer stop as missing geometry, or apply the viewer's stop exclusions. Ambiguous content must yield a clear limitation or unavailable export, not invented continuity.
- [ ] **Output:** download a schema-compatible GPX 1.1 file for the selected session, with correctly encoded XML and original supported values. Explain exclusions and unsupported fields before download, including why this is not a full-fidelity FIT backup. No usable geographic content means no empty-success download. Any partial export identifies what geographic content was left out and requires an informed download action.
- [ ] **Flow and feedback:** the initial page exposes file choice/drop and concise supported scope above help. Processing has visible progress/cancellation. Loaded results show selected session identity, geographic preview/summary, preservation/loss notice and Download GPX together where practical. Changing session updates that same result and output. Invalid replacement preserves a usable previous result; clear/replace/retry are understandable. Download feedback must not claim that the browser saved a file or that another application imported it successfully.
- [ ] **Example:** provide one public-safe, permissioned or synthetic FIT activity with documented provenance through the real decoding/export path. Label it as an example and make choosing a personal file obvious. Reuse example import protection so a late load cannot replace newer work.
- [ ] **Optional preview and retained download:** Preview converted GPX opens the actual generated GPX through the existing validation/import pipeline and viewer components within the converter page. No route handoff, manual download/reselection or replacement of the original FIT is required. Keep the primary Download GPX action visible beside the converted file's identity during preview, including phone map views, and after closing it. Closing restores the conversion summary and focus to the preview action, preserving source, selected session and generated bytes in memory. Preview controls must not alter those bytes. Changing source/session updates or invalidates preview and download together; late work must not restore stale output. A preview rendering failure retains an independently valid download and offers retry/close; invalid generated GPX blocks download with clear recovery. Do not add activity URLs or persistent storage. Test identical downloaded bytes before, during and after preview; closing/reopening, source/session changes and failures; and visible download access with keyboard/touch at all four required viewports. Session-only retention must not be described as permanent saving.
- [ ] **Privacy and costs:** decode and export on the person's device using existing static infrastructure; no activity data, filenames or sensor values enter requests, URLs, page metadata or storage. Existing map requests remain disclosed, and basemap failure must not prevent export. Add no backend, paid service, analytics or ads. Browser/network checks use synthetic data.
- [ ] **Interoperability and correctness:** verify known-answer coordinates, times, elevation, order and section structure independently of GPSGoblin's GPX parser, using GPX schema validation and another GPX consumer. Include single/multiple sessions, indoor/no GPS, missing data, stationary portions, malformed input and source time anomalies. A My Maps compatibility claim specifically requires a permitted synthetic-file test there; otherwise use generic tested GPX compatibility wording. Run representative ordinary and large FIT cases on named desktop/mobile browsers, record cancellation/responsiveness and limitations, and seek owner agreement before any hard resource cap.
- [ ] **Whole-page UX:** exercise initial, processing, loaded, changed-session, download, error, replacement and no-GPS states at 1440×900, 1280×720, 390×844 and 375×667 under [the UX workflow](agents/ux.md). Record fold/scroll position, visible feedback, keyboard and touch, focus and readable copy. On phones place download and losses beside the selected-session summary, with a deliberate preview disclosure if needed; do not require repeated travel between controls and feedback. Verify relevant contrast and avoid carrying a confirmed task-blocking issue from #44 into the new flow.
- [ ] **Discovery:** publish only the functioning converter route with truthful title, description, canonical and supporting HTML; link it from the homepage and relevant viewer help and include it in the production sitemap. Explain what conversion preserves and when the destination may still reject a file. Do not create provider landing pages, claim universal compatibility or promise rankings. Record Search Console indexing/performance if existing access is available; absent access does not block a useful release or permit new telemetry.
- [ ] **Release evidence:** update spec/support/limitations and commercial records to match accepted scope and actual status. Pass focused and regression tests, typechecking, lint, `pnpm knip` with no findings, `pnpm format:check`, the static build and the required complete CI suite. Complete review on a numbered ticket branch; merge/deployment remain subject to the owner's authorisation. Verify the public workflow and issue closure after the authorised release process.

## Assessment and stopping point

Technical completion is one reliable local-file-to-download workflow with independently verified output and a published compatibility boundary. It is not proof of acquisition or profitability.

At release, record the date and existing search baseline if available. Review relevant search impressions, queries and clicks after roughly four weeks, using another review around eight weeks where data are sparse. Assess task success through permitted representative files and available feedback, separately from search visibility. Keep commercial impact unknown if data cannot be accessed. Review monetisation readiness at the release checkpoint; actual profit assessment requires revenue and operating-cost records for matching periods once a revenue mechanism is active.

Do not automatically append batch conversion, FIT courses, TCX conversion or a full FIT viewer. Reassess against evidence. Confirmed preservation/security defects block release; a verified indexing failure may make a bounded discovery fix more urgent. Decoder incompatibility or inability to produce trustworthy output requires a new scope decision rather than silent reduction of the promised behaviour.
